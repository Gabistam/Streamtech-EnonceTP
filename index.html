Setup

Installer l'environnement

On crée le projet avec Vite : beaucoup plus rapide que Create React App, et c'est la méthode recommandée aujourd'hui.

  1. Vérifier Node.js

    Ouvre ton terminal. Il te faut Node.js 20.19 ou plus récent (version exigée par les versions actuelles de Vite). Sinon, installe la version LTS depuis nodejs.org.

  2. Créer le projet avec Vite

    Si Vite pose des questions, garde React et JavaScript. Pas besoin de TypeScript pour l'instant.

  3. Installer Bootstrap

    Rapide à mettre en place, rendu professionnel tout de suite. Ajoute ensuite l'import tout en haut de src/main.jsx.

    L'application aura plusieurs pages (films, todos, contact) : il faut un routeur pour gérer la navigation.

  5. Lancer le serveur de développement

    Ouvre http://localhost:5173 : la page par défaut de Vite doit s'afficher.

Théorie

Les composants fonctionnels

Composants

En React, tout est composant. Comme une brique LEGO : petit, réutilisable, assemblable. Un composant est une fonction JavaScript qui retourne du JSX (du HTML dans du JS).

  1. Le nom commence toujours par une majuscule.
  2. Il retourne du JSX.
  3. Un seul élément racine (d'où le <div> qui englobe tout).

Théorie

Le state avec useState

State

Les props viennent de l'extérieur. Le state est la mémoire interne du composant : un compteur, un champ de formulaire, un bouton on/off.

  • useState(0) : état initial à 0
  • count : valeur actuelle
  • setCount : fonction qui modifie l'état

Piège classique

Ne jamais modifier le state directement

❌count = count + 1 : React ne voit pas le changement, l'écran ne se met pas à jour.
✅setCount(count + 1) : React enregistre la nouvelle valeur et relance le rendu.

Même règle pour les props : elles sont en lecture seule. Un composant ne modifie jamais les props qu'il reçoit.

Théorie

Appeler une API avec fetch

API

fetch est la fonction native de JavaScript pour les requêtes HTTP. Deux écritures : les promesses chaînées, ou async/await, plus lisible.

Bonne pratique

Isoler les appels dans un service

On regroupe tous les appels TMDB dans src/services/tmdbApi.js. Les composants appellent des fonctions claires (getPopularMovies(), searchMovies()…) sans connaître les URL.

Chaque fonction transforme la réponse brute de l'API en un format uniforme : id, title, year, rating, poster, overview. Nos composants restent identiques, que les données viennent de la liste populaire, d'une recherche ou d'un genre.

Notion clé

Le debounce

Effets

Sans précaution, taper « Matrix » enverrait une requête à chaque lettre. Le debounce attend 500 ms de silence avant de lancer la recherche.

  1. À chaque frappe, searchTerm change et l'effet se relance.
  2. L'effet programme la recherche dans 500 ms avec setTimeout.
  3. Si une nouvelle frappe arrive avant, la fonction de nettoyage annule le timer précédent avec clearTimeout.
  4. Seule la dernière frappe déclenche vraiment l'appel API.

Pratique

Recherche en temps réel dans App

Effets

Approfondir

Le nettoyage (cleanup)

Effets

Le return d'un effet nettoie quand le composant se démonte, ou juste avant la prochaine exécution de l'effet.

Approfondir

Plusieurs useEffect

Effets

Un composant peut avoir plusieurs effets. C'est même recommandé : une responsabilité par effet.

Règle d'or

Déclarer toutes les dépendances

Toute variable du composant utilisée dans l'effet doit figurer dans le tableau de dépendances. Sinon, l'effet travaille avec une valeur périmée.

Théorie

Les formulaires contrôlés

Formulaires

Dans un formulaire contrôlé, la valeur du champ vient du state, et chaque frappe met le state à jour.

Avantages : validation en temps réel, contrôle total sur les données, réinitialisation facile, synchronisation avec le state.

À savoir

JSONPlaceholder simule les écritures

JSONPlaceholder est une API de simulation. Les ajouts, modifications et suppressions renvoient une réponse comme si tout avait fonctionné, mais rien n'est réellement enregistré côté serveur.

C'est pour ça qu'on met aussi à jour le state local après chaque appel : c'est lui qui fait foi à l'écran. Recharge la page et tu retrouveras les 20 tâches d'origine.

Conséquence : tous les nouveaux todos reçoivent l'id 201. Évite de les modifier entre eux, ils partagent la même key.

Bonus 2 · Théorie

useReducer : des états complexes

État global

Quand le state regroupe plusieurs valeurs liées et beaucoup d'actions, on centralise la logique dans un reducer, comme un Redux miniature.

Choisir

useState ou useReducer ?

useState quand…useReducer quand…
Le state est simple : une valeur, un objet simpleLe state est un objet à plusieurs propriétés liées
Il y a peu de modificationsIl y a beaucoup d'actions différentes
La logique reste simpleLes transitions sont complexes ou réutilisables
